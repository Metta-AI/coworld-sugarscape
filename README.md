# Coworld Sugarscape

This repository is a native Nim port of the Digital Terraria Lab (DTL)
Sugarscape implementation. Its compatibility oracle is DTL commit
`a46ec6ff909e2bc73a4c9e9f36b2aed160eccad8`, vendored under
`reference/dtl-python/`.

The project has two non-negotiable goals:

- reproduce the pinned Python model's deterministic behavior and serialized
  outputs byte for byte; and
- run the simulation as optimized native code, with no Python dependency in
  the production executable.

The complete behavioral contract and implementation order are in
[`rules.md`](rules.md).

## Current compatibility

The native core currently covers:

- CPython 3.12-compatible seeded MT19937, `random()`, `randbelow()`, and
  `shuffle()`;
- DTL configuration defaults, overlays, legacy aliases, and the normalization
  exercised by all 29 shipped example configurations;
- peak-generated sugar and spice worlds, cardinal and radial range tables,
  wraparound, immediate neighborhoods, growback, seasons, and pollution
  diffusion;
- deterministic initial placement and base agent endowments;
- asynchronous movement, collection, metabolism, aging, and aggregate runtime
  statistics for the base model;
- CPython-compatible JSON float and object formatting.

`tests/fixtures/base_small.oracle.json` is generated by the pinned Python
source. The native simulation matches all 7,044 bytes through termination.

The interaction-heavy layers—combat, reproduction, culture, trade, lending,
disease, ethical decision models, agent logs, and the Coworld service/viewer
boundary—remain under active porting. The repository does not claim full DTL
compatibility until every gate in `rules.md` passes.

## Build

Nim 2.2 or newer is required.

```bash
mkdir -p build
nim c -d:release --path:src -o:build/sugarscape src/sugarscape.nim
```

Run a configuration with the upstream-compatible CLI:

```bash
build/sugarscape --conf tests/fixtures/base_small.json
```

The `logfile` setting controls JSON output. As in DTL, an existing logfile is
opened in append mode. CSV output is part of the pending interaction/output
compatibility layer.
