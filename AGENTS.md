# AGENTS.md

## Purpose

This is a native Nim compatibility port of DTL Sugarscape, not a MettaGrid
template. Read `rules.md` before changing simulation behavior.

## Behavioral authority

The source under `reference/dtl-python/` is pinned at commit
`a46ec6ff909e2bc73a4c9e9f36b2aed160eccad8` and is the oracle. Preserve its
observable bugs unless `rules.md` explicitly excludes them. Do not alter the
vendored source except when replacing it wholesale with a deliberately chosen
new upstream pin.

Deterministic compatibility includes random-number consumption, iteration
order, floating-point operation order, log key order, numeric spelling, and
whitespace. A structurally equivalent JSON document is not sufficient.

## Architecture

- `src/sugarscape/py_random.nim`: CPython random compatibility.
- `src/sugarscape/configuration.nim`: parsing and normalization.
- `src/sugarscape/environment.nim`: contiguous cells and static range tables.
- `src/sugarscape/agents.nim`: agent state and deterministic endowments.
- `src/sugarscape/diseases.nim`: disease definitions and immune-system state.
- `src/sugarscape/simulation.nim`: activation loop and runtime statistics.
- `src/sugarscape/py_json.nim`: CPython `json.dumps` formatting.
- `src/sugarscape/coworld.nim`: synchronous population-policy and replay edge.
- `viewer/`: sources for the browser broadcast. `tools/build_viewer.py` inlines
  them with the vendored typefaces and art batch into the generated
  `src/sugarscape/viewer.html`, which `coworld.nim` embeds with `staticRead`.
  Edit `viewer/`, never the generated file, and rebuild before committing;
  `tools/test_all.sh` fails on a stale one.
- `src/sugarscape/art/`, `src/sugarscape/fonts/`: the viewer's art batch and
  typefaces. The hosted embed is a sandboxed iframe behind a proxy that rewrites
  the base href and cannot reach a CDN, so the served document must pull no
  external sub-resource and every asset ships inlined.
- `players/greedy/`: bundled deterministic certification policy.
- `tests/nim/`: focused native tests.
- `tests/fixtures/`: small configurations and Python-generated byte oracles.

Keep hot state in contiguous value storage and use stable integer IDs rather
than reference-heavy object graphs. Compatibility wins over optimization when
the two conflict.

## Commands

```bash
nimby use 2.2.6
nimby sync nimby.lock
tools/test_all.sh
nim c -d:release --opt:speed --nimcache:.nimcache/release \
  --path:src -o:.build/sugarscape src/sugarscape.nim
```

Nimble cannot resolve the private `bitworld` package from the public package
registry; use the pinned Nimby environment and `tools/test_all.sh`. Use an
explicit writable `--nimcache` when invoking `nim` directly. Never add Python
or an embedded interpreter to the production runtime.

`config.nims` disables floating-point contraction to preserve CPython operation
boundaries. Keep it active in tests, native builds, and container builds.

## Change discipline

Add a focused state-transition oracle before changing a feature, then add a
byte-level log comparison when the layer is complete. Run the full native suite
after any change to RNG, initialization, movement, statistics, Python numeric
type tracking, or JSON formatting. Run all 29 differential examples after a
change to simulation semantics.

Update `README.md` and `rules.md` when compatibility scope, commands, public
interfaces, or architecture changes. Do not describe a layer as complete until
its fidelity gates pass.
