# AGENTS.md

## Purpose

This is a native Nim compatibility port of DTL Sugarscape, not a MettaGrid
template. Read `rules.md` before changing simulation behavior.

## Behavioral authority

The source under `reference/dtl-python/` is pinned at commit
`a46ec6ff909e2bc73a4c9e9f36b2aed160eccad8` and is the oracle. Preserve its
observable bugs unless `rules.md` explicitly excludes them. Do not alter the
vendored source except when replacing it wholesale with a deliberately chosen
new upstream pin.

Deterministic compatibility includes random-number consumption, iteration
order, floating-point operation order, log key order, numeric spelling, and
whitespace. A structurally equivalent JSON document is not sufficient.

## Architecture

- `src/sugarscape/py_random.nim`: CPython random compatibility.
- `src/sugarscape/configuration.nim`: parsing and normalization.
- `src/sugarscape/environment.nim`: contiguous cells and static range tables.
- `src/sugarscape/agents.nim`: agent state and deterministic endowments.
- `src/sugarscape/simulation.nim`: activation loop and runtime statistics.
- `src/sugarscape/py_json.nim`: CPython `json.dumps` formatting.
- `tests/nim/`: focused native tests.
- `tests/fixtures/`: small configurations and Python-generated byte oracles.

Keep hot state in contiguous value storage and use stable integer IDs rather
than reference-heavy object graphs. Compatibility wins over optimization when
the two conflict.

Use an explicit writable `--nimcache` when invoking `nim` directly. Never add
Python or an embedded interpreter to the production runtime.

## Change discipline

Add a focused state-transition oracle before porting a feature, then add a
byte-level log comparison when the layer is complete. Run the base log parity
test after any change to RNG, initialization, movement, statistics, or JSON
formatting.

Update `README.md` and `rules.md` when compatibility scope, commands, public
interfaces, or architecture changes. Do not describe a layer as complete until
its fidelity gates pass.
