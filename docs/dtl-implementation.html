§ 1 — Provenance

What DTL is, and what "byte-for-byte" actually means

Sugarscape is the founding artificial-society model: a lattice of cells that grow a renewable resource, and a population of agents that look around, move to the best cell they can see, eat, and die. Epstein and Axtell used it to show that recognisable macro-phenomena — skewed wealth distributions, migration waves, trade prices, epidemics — emerge from local rules with no global coordination.

The Digital Terraria Lab (DTL) implementation is a Python descendant of that model, maintained by Nate Kremer-Herman and contributors. It is not a minimal teaching implementation. It carries the whole book — growback, seasons, pollution, sex and reproduction, cultural tags, combat, spice and bilateral trade, credit, disease, inheritance — and then adds a layer the book does not have: pluggable decision models, in which an agent's choice of where to move is filtered through an ethical theory rather than through pure greed.

The archived v1 of this repository is a Nim port of that Python. The port's contract was not "behaves similarly" but produces identical log bytes for identical seeds. That contract is what makes DTL worth reading closely: every incidental detail of the Python — the order dictionaries are iterated, the exact rejection loop inside random.shuffle, whether a division yields 0 or 0.0, how CPython renders a float in JSON — became part of the specification.

Why this matters for v2

Reading DTL as "a Sugarscape" tells you what the model is for. Reading it as the v1 port had to tells you what the model is: a specific sequence of state mutations and random draws. v2 needs the first to choose its mechanics and the second to know precisely which behaviours it is choosing to keep, change, or drop.

Concretely, the Nim port had to reimplement CPython's Mersenne Twister including init_by_array seeding and the rejection sampling inside _randbelow; reproduce json.dumps float formatting and unbounded integers; and preserve outright bugs, such as an inverted boundary test in the cell-neighbour lookup, which it does with an explicit flag named preserveSouthBoundaryBug. That flag is the clearest single illustration of what fidelity cost.

§ 2 — Structure

The object graph, and the back-references that hold it together

There are five classes and one small hierarchy of subclasses. The important structural fact is that ownership runs downward but reference runs in both directions: every cell knows its environment, every environment knows its simulation, and every agent reaches global configuration by walking self.cell.environment.sugarscape. Agent code reads and writes simulation-level state through that chain constantly.

Two consequences follow from this shape and both matter for a port. First, there is no double buffering anywhere: agents act sequentially and asynchronously within a timestep, so the fifth agent to act sees a world already changed by the four before it. Second, because Sugarscape.agents is shuffled in place each timestep, the canonical agent list is permanently permuted — which affects not only activation order but also the order in which deaths are processed and log records are emitted.

§ 3 — The world

Grid, resource peaks, growback, seasons, pollution

The environment is a width × height array indexed grid[x][y], by default 50 × 50, and by default a torus: environmentWraparound is true, so column width−1 is adjacent to column 0. Each cell carries a current and a maximum amount of two commodities, sugar and spice, plus a pollution level and a season.

Resource peaks

The classic terrain is generated, not authored. Each configured peak [x, y, maxValue] is painted by addResourcePeak as a cone that is quantised upward by ceil into discrete bands, and peaks compose by taking the maximum, so overlapping peaks never sum:

radius = ceil(sqrt(2 · (H + W))) → 15 on a 50×50 grid dispersion = sqrt(max(px, W−px)² + max(py, H−py)²) · radius/W value(i,j) = ceil( min( 1 + maxValue · (1 − dist/dispersion), maxValue ) ) cell.maxSugar = max(cell.maxSugar, value(i,j)) peaks compose by max, never sum

The defaults place sugar peaks at (35,15) and (15,35) and spice peaks at (35,35) and (15,15), each capped at 4 — the familiar two-mountain sugarscape, with spice on the opposite diagonal so that the two commodities are spatially anti-correlated and trade has something to do.

Where agents start

Agents are seeded into quadrants, not uniformly. Quadrant 1 is the top-left, numbered clockwise; environmentQuadrantSizeFactor shrinks each quadrant toward its corner. Placement shuffles the cell list inside each active quadrant, shuffles the quadrant order, then deals agents round-robin across quadrants. With the default [1,2,3,4] the whole grid is eligible, but restricting to one quadrant is how the book's migration figures are reproduced.

Growback, seasons, pollution

Every timestep, before any agent acts, the environment runs three things in order: updateSeasons, updatePollution, then doCellUpdate.

ProcessRuleControlled by
Growback sugar = min(sugar + rate, maxSugar), applied to every cell. Rate 1 is the book's "constant growback"; a rate ≥ maxSugar gives immediate growback. environmentSugarRegrowRate, environmentSpiceRegrowRate
Seasons The grid is split at an equator into two hemispheres holding opposite seasons, which swap every seasonInterval steps. Cells in the wet season grow back every step; cells in the dry season grow back only on the tick when a countdown of length seasonalGrowbackDelay resets. environmentSeasonInterval, environmentSeasonalGrowbackDelay, environmentEquator
Pollution Two sources, both charged to the cell: production pollution when an agent harvests, consumption pollution when an agent metabolises. Both are active only inside a configured timeframe. environmentSugarProductionPollutionFactor and its three siblings, environmentPollutionTimeframe
Diffusion On a delay countdown, every cell computes the mean pollution of its neighbours into a flux field, then all cells adopt their flux at once. This is the one genuinely synchronous update in the model. environmentPollutionDiffusionDelay, environmentPollutionDiffusionTimeframe

Pollution does not damage agents directly. It works entirely through cell valuation: an agent divides a cell's resources by 1 + pollution when deciding where to move, so a polluted cell simply stops looking attractive. This is what produces the book's result that agents pollute a region and then abandon it.

§ 4 — Adjacency

Two different notions of "nearby", used for different things

This is the distinction most easily missed on a first read, and getting it wrong changes almost every downstream behaviour. Each cell carries two separate adjacency structures, computed once at startup and never recomputed.

cell.ranges is a memoised table built once by findCellRanges: a dict from integer band → {cell → distance}, sized to the largest vision or movement any agent could ever have (including disease bonuses). Radial geometry is used only when both agentVisionMode and agentMovementMode are "radial"; otherwise everything is cardinal.

An agent's per-turn candidate set is then min(vision, movement, maxCellDistance) bands unioned together. Note what this means: vision and movement are not independent in DTL. An agent that can see six cells but move one considers only one cell in each direction — it cannot look at a distant peak and walk toward it over several turns.

Deviation from the book

The current cell is never a member of cellsInRange. Unless the candidate list comes back empty, an agent always relocates, even when every reachable cell is worse than where it is standing. In Growing Artificial Societies the agent evaluates its own site alongside the others and may stay put.

§ 5 — The agent

Endowments, welfare, and how a cell is chosen

An agent is a bundle of scalar endowments plus a social network. The endowments that drive the core loop are small in number:

Endowments are not drawn independently per agent. They are generated as a deterministic ramp — walk from min to max in the smallest increment implied by the configured decimals, wrapping back to min at the top — and then that list is shuffled. This guarantees an exactly uniform spread across the population rather than a sampled approximation of one, and it is why replacement agents drawn later from the same endowment pool follow the same distribution as the founders.

The welfare function

Everything an agent values — a cell, a trade, a combat opportunity — is scored with one function, a Cobb–Douglas utility over the two commodities, with each exponent set to that commodity's share of the agent's total metabolism:

m_s, m_p = sugar, spice metabolism M = m_s + m_p W(x_s, x_p) = (w_s + x_s − m_s·L) m_s/M · (w_p + x_p − m_p·L) m_p/M w_s, w_p current holdings x_s, x_p the prospective reward L lookaheadFactor negative terms are clamped to 0

The consequence is that an agent with heavy sugar metabolism and no spice metabolism scores cells purely on sugar, while a balanced agent needs both and will value a cell holding some of each above a cell holding a lot of one. That single asymmetry is what makes trade profitable later.

Two optional modifiers wrap this. agentTagPreferences replaces the metabolic exponents with ones derived from the proportion of zeroes and ones in the agent's cultural tag string, so culture starts to determine taste. And if any of the four in-group factors — ageism, racism, sexism, tribalism — is enabled, the resulting welfare is multiplied by a modifier computed from the proportion of a candidate cell's neighbours that are in-group, which biases movement toward one's own kind.

Choosing a cell

The retaliation filter deserves a note, because it is the book's combat rule and it is subtle. Before scoring, the agent surveys every tribe visible to it and records the wealth of that tribe's richest visible member. A candidate cell occupied by prey is discarded if that prey's tribe fields someone richer than the attacker would be after winning. Combat is therefore deterred not by the victim's strength but by its neighbours'.

§ 6 — The loop

The timestep, in exact order

This is the spine of the model. Everything else is a subroutine hanging off it. The order is not incidental — it decides, for instance, that resources regrow before anyone moves, that an agent harvests before paying its metabolism, and that a starving agent never gets to trade its way out of death that turn.

The agent's turn, step by step

  1. moveToBestCell()Rank every reachable cell, apply the decision model if one is active, then either walk into the cell or fight whoever is standing there. Resources are not collected yet.shuffle
  2. updateNeighbors()Refresh the adjacent-agent list and fold those agents into the social network: visit counts, observed marginal rates of substitution, and the friend list ranked by cultural Hamming distance.
  3. collectResourcesAtCell()Take all sugar and spice at the cell — there is no harvest cap — update the exponential moving average of income (α = 0.05, used for creditworthiness), charge production pollution, and zero the cell.
  4. doUniversalIncome()If the configured interval has elapsed, add the flat basic-income grant of each commodity.
  5. doMetabolism()Subtract metabolism, charge consumption pollution. Death by starvation if either holding goes negative, or hits zero for a commodity the agent actually burns. A dead agent's turn stops here.
  6. doTagging()For each adjacent agent, pick a random position in the cultural tag string and overwrite the neighbour's bit at that position with your own; recompute their tribe. This is the book's cultural-transmission rule.shuffle + randrange
  7. doTrading()Repeated bilateral barter with each adjacent agent whose marginal rate of substitution differs, until no further trade improves both parties.shuffle
  8. doReproduction()If fertile, pair with each compatible adjacent agent and place a child in an empty cell adjacent to either parent; both parents pay.shuffle ×2, seeded draws
  9. doLending()Settle any matured loans first, then offer new ones to adjacent agents who are of reproductive age but currently too poor to be fertile.shuffle
  10. doDisease()Advance incubation, run the immune response, then attempt to transmit one randomly chosen disease to each adjacent agent.shuffle ×2, randrange, uniform ×2
  11. doAging()Increment age; die if maxAge is reached and finite. A dead agent's turn stops here.
  12. findCellsInRange()Recompute the reachable set from the new position, for use next turn and by other agents' ethical evaluations this turn.
  13. updateHappiness()Recompute the five happiness components — wealth, health, social, family, conflict — and their sum.
  14. updateRuntimeStats() · updateValues()Emit the per-agent log record; updateValues is the subclass hook where dynamic selfishness and the temperance rule-base are updated.
Ordering consequences worth internalising

Growback happens once for the whole grid before any agent moves, so all agents compete for the same regrown field. Because agents then act one at a time on the live grid, being early in the shuffled order is a real advantage — the first mover harvests the richest cell, and later movers evaluate a field that has already been stripped. Activation order is therefore a genuine source of variance, not just of nondeterminism.

§ 7 — Interaction

The seven modules that hang off the turn

Each of these is off by default and switched on by giving agents a nonzero endowment for it. They compose freely, which is what the example configurations in examples/ exercise — each one maps to a specific figure or page range in Growing Artificial Societies.

Combat

Enabled by agentAggressionFactor > 0. An aggressive agent's move is its attack: moveToBestCell routes through doCombat, which loots min(environmentMaxCombatLoot, victim's holdings) of each commodity, kills the occupant, and takes the cell. Valid prey must be of a different tribe and no wealthier than the attacker; the retaliation filter described in §5 removes the rest. Aggression also inflates perceived value — a highly aggressive agent multiplies the prospective loot by its aggression factor when scoring, so combat becomes attractive beyond its literal payoff.

Culture and tribes

Agents carry a binary tag string of length agentTagStringLength. Tribe membership is a function of how many zeroes the string contains, bucketed evenly across environmentMaxTribes:

tribeSize = (tagStringLength + 1) / numTribes tribe = min( ceil( (zeroes + 1) / tribeSize ) − 1, numTribes − 1 )

Because tagging overwrites one bit of a neighbour's string per turn and tribe is recomputed immediately, cultural conversion is continuous: an agent surrounded by another tribe drifts into it. Tags also drive the friend network (nearest by Hamming distance), optionally the welfare exponents, and — through tribe — combat eligibility.

Trade

Enabled by agentTradeFactor > 0. Each agent computes a marginal rate of substitution from how urgently it needs each commodity relative to its metabolism. MRS > 1 means spice is relatively abundant, so the agent should sell spice.

Reproduction

Requires sexes (agentMaleToFemaleRatio), fertility windows, and a nonzero agentFertilityFactor. An agent is fertile when it is inside its fertility age window and holds at least as much of each commodity as it started life with — so wealth is literally the licence to breed. Each parent pays startingResource / (fertilityFactor × 2), and the child's initial endowment is exactly the sum of those two payments: reproduction transfers wealth, it does not create it. Scalar traits are inherited by coin flip per trait, tag strings bit by bit with random resolution of mismatches, and the decision-model settings as one inseparable block from a single parent.

Disease and the immune system

A disease is a bit string. An agent's immune system is a longer bit string. Infection is possible only if the disease's string does not appear exactly somewhere in the immune system; recovery works by flipping one immune-system bit per timestep toward the disease's pattern at the best-matching offset, so recovery time is a function of the initial Hamming distance.

Credit

There are two kinds of lender. A fertile agent may lend only what it holds above its own reproduction threshold; an agent past fertility age has no such reservation and will lend up to half of each holding. Borrowers are agents of reproductive age who are not fertile purely because they are too poor. A loan's size is capped by the borrower's shortfall and the lender's available amount, the rate is min(1, lendingFactor × baseInterestRate), and the borrower must pass a creditworthiness test against its moving-average income net of existing debt. On maturity, a borrower who cannot pay in full surrenders half of each holding and the remainder is rolled into a fresh loan with interest compounded.

Inheritance

On death, remaining wealth is split evenly among living children, sons, daughters, or friends depending on agentInheritancePolicy. This is the mechanism that turns the wealth distribution sharply more unequal, which is the point the book uses it to make.

Happiness

Not a book mechanism — a DTL addition, and the objective the Leader agent optimises. Five components sum to a scalar: wealth relative to the population mean (passed through erf), health (sick or not), social (friend count against capacity), family (living children and mates, penalised for sick or dead ones, also through erf), and conflict (positive after a kill only if the agent is highly aggressive, negative otherwise).

§ 8 — Decision models

Where an ethical theory plugs into a greedy agent

This is DTL's substantive addition to Sugarscape, and it is deliberately narrow in scope: a decision model changes one decision only — which cell to move to. Trading, mating, lending and combat rules are untouched. The plug point is a single method, findBestEthicalCell(cells, greedyBestCell), which the base Agent implements as "return the greedy answer" and each subclass overrides.

Selection happens at construction: configureAgents inspects the endowment's decisionModel string and instantiates a subclass instead of a plain Agent. Suffixes on the string tune it further — NoLookahead and HalfLookahead pin the lookahead factor, Dynamic enables drifting selfishness, PECS selects the elaborated temperance variant. Crucially, the model is consulted only when agentDecisionModelFactor > 0; otherwise even a Bentham agent behaves greedily.

ModelClassHow it scores a cell

rawSugarscape		Agent No override. Pure Sugarscape rule M: closest cell with the highest welfare.
benthamBentham Felicific calculus. For every agent in the neighbourhood, compute intensity, duration, certainty, proximity and extent for the candidate cell, plus discounted future terms standing in for purity and fecundity. Other agents' values enter as opportunity costs, negated and weighted by 1 − selfishnessFactor. Selfishness defaults to 0.5.
altruistBentham Same calculus with selfishnessFactor = 0: the agent's own welfare carries no weight at all.
egoistBentham Same calculus with selfishnessFactor = 1: everyone else carries no weight. Differs from none in that it still scores by the felicific terms rather than raw welfare.
negativeBenthamBentham Selfishness −1 switches the return type: the cell yields a pair (happiness, unhappiness) and cells are ranked to minimise harm first, maximise good second.

Combinatorial, and intended as an upper bound rather than a runnable configuration.

Four bias factors — ageism, racism, sexism, tribalism — cut across all of this. They appear twice, in two different forms. In the ordinary welfare path they scale a cell's value by the proportion of its neighbours who are in-group. In the Bentham path they instead weight each neighbour's contribution to the utility sum by whether that neighbour is in-group. So the same configured factor means "I prefer to live among my own" in one model and "I count their suffering less" in the other.

Note for v2

The decision-model layer is where DTL's research interest lives, and it is also the least book-derived part of the system — the least constrained by any external specification, and the most freely reinterpretable.

§ 9 — Determinism

One global stream, and the seeded excursions off it

Every random draw in DTL comes from CPython's single module-level random instance. There is no per-agent generator and no injected RNG. Setting seed in the configuration seeds that one stream at startup; the whole run is a deterministic function of it, and reproducibility depends entirely on every draw happening in exactly the same order.

But drawing endowments straight from that stream would make each attribute's values depend on the iteration order of a dictionary — brittle, and hostile to adding a new attribute later. DTL's answer is a recurring idiom: save the stream, reseed it from a hash of the attribute's name, do the shuffle, restore the stream.

The trick is elegant but leaves a sharp edge: inside findChildEndowment the excursion is not closed between every use. The tag, racial-tag and immune-system blocks each reseed, and the depression roll that follows the racial-tag block draws from that block's stream rather than the main one. Any reimplementation has to reproduce that, not clean it up.

What a faithful port has to reproduce

SurfaceRequirement
GeneratorMT19937 with CPython's init_genrand and init_by_array seeding, including how an integer seed is decomposed into 32-bit limbs.
Integer draws_randbelow uses getrandbits(k) with rejection until the value is in range — not a modulo. Getting this wrong desynchronises the stream on the first out-of-range draw.

Hash seedingint(md5(name).hexdigest(), 16) + timestep is a 128-bit integer; it must be converted to limbs exactly as CPython would.
NumericsPython 3 true division always yields a float, so 0 / n is 0.0 and serialises differently from 0. Integers are unbounded.

The archived v1 implements all six — py_random.nim for the first four, py_json.nim for the last two, the latter carrying unbounded Python integers through a tagged string so they survive Nim's 64-bit JSON nodes. That is the concrete meaning of "byte-for-byte".

Where the shuffles actually change outcomes

  • Agent activation order, reshuffled every timestep, decides who harvests the regrown field first.
  • Candidate cell order, because the ranking sort is stable — cells tied on both welfare and distance keep shuffled order, and when total metabolism is zero every cell ties.
  • Neighbour iteration order in tagging, trade, reproduction, lending and disease — who you interact with first determines what resources are left for the rest.
  • Empty-cell selection for newborns, and which disease an infectious agent transmits to each neighbour.
§ 10 — Configuration

The experimentalGroup key is worth singling out. Setting it to a group name — a sex, a race, a decision model, "sick", "depressed", a specific disease or age band — causes every runtime statistic to be computed three times: for the whole population, for the group, and for its complement, with an additional matrix of cross-group interaction counts for combat, trade, lending, reproduction and infection. That is the machinery DTL's own research runs on.

§ 11 — Fixed points

The behaviours a byte-compatible port had to preserve

These are the places where DTL's behaviour is decided by an accident of implementation rather than by the model. They are listed not to criticise the code but because they are precisely the load-bearing details: the v1 port had to reproduce every one of them, and v2 has to make an explicit decision about every one of them.

WhereBehaviourEffect
cell.findSouthNeighbor The non-wraparound bounds test is inverted relative to north/east/west: it returns None when y + 1 < height − 1. On a non-toroidal grid, most cells have no south neighbour at all while the bottom row wraps. The v1 port keeps it behind a flag named preserveSouthBoundaryBug.
movement candidates The agent's current cell is never in cellsInRange. Agents relocate every turn regardless of whether staying would be better. Departs from the book's rule M.
findWelfare With zero total metabolism, both exponents are zero and welfare is 1 for every cell. Movement becomes pure shuffle order. Any configuration with no metabolism is effectively a random walk.
Depression.trigger Uses *= with ceil(value × penalty) where assignment was intended, and the metabolism penalty is > 1. Depressed agents get explosively inflated movement and metabolism, and overeat rather than undereat. Acknowledged in an in-source TODO.
findNearestHammingDistanceInDisease The sliding window runs range(len(immuneSystem) − len(diseaseTags)), one short of the last valid offset. The final alignment is never tested, so an agent immune only at the tail of its immune string is not recognised as immune.
pollution diffusion The two diffusion loops index grid[i][j] with i running over height and j over width. Correct only on square grids; a non-square grid indexes wrongly or raises.
sugarLastProduced The test sugar + rate != sugar is just "rate ≠ 0"; it does not detect that a cell was already at maximum. The reported "environment wealth created" statistic overcounts, charging growth to saturated cells.
canTradeWithNeighbor Returns False to refuse but falls off the end returning None to permit. Works only because the caller compares against False explicitly. Any tightening to a truthiness test inverts trade.
updateLoans, payDebt Both mutate the creditor/debtor lists while iterating them. Some loans are skipped in a given pass. The skipping pattern is deterministic and therefore part of the observable behaviour.
agent endowments The universalSpice range takes its maximum from universalSugar[1]. Basic spice income silently follows the sugar ceiling.
Cell.hemisphere Computed from x ≥ equator, while the season actually assigned in setCell uses y < equator. Harmless today — hemisphere is unused — but the two disagree, so anything that starts reading it will be wrong.
Sugarscape.agents Shuffled in place each timestep rather than iterated over a shuffled copy. The canonical list is permanently permuted, which also reorders death processing and per-agent log records.
The takeaway for v2

None of these are hard to fix. The point is that fixing any one of them breaks byte-compatibility with every recorded DTL run, which is why v1 preserved them all. A from-scratch successor is free of that constraint — but it should inherit the discipline that made the constraint satisfiable: one explicit random stream, a single documented activation order, and no reliance on container iteration order anywhere behaviour depends on it.
